# Maintenance Policy

How this project is versioned, supported, and eventually retired. Bilingual:
this is the English reference; see [MAINTENANCE.zh.md](./MAINTENANCE.zh.md).

## Versioning

SemVer with pre-release tags during the DSH developer-preview window
(`0.1.0-alpha.1` → `0.1.0-beta.1` → `0.1.0-rc.1` → `0.1.0`). Every release
updates, in the same commit:

- `package.json` `version`
- `compatibility.json` (`pluginVersion` + the tested DSH matrix)
- `docs/COMPATIBILITY.md` + `.zh.md` (the human-readable matrix)

`scripts/verify-docs.mjs` fails the build if any pair drifts.

## Support windows

| Channel | Window |
|---|---|
| pre-releases (`alpha`/`beta`/`rc`) | until the next pre-release of the same minor |
| `0.x` stable | best effort; security fixes prioritized |
| a released DSH version listed in the matrix | supported until the matrix entry is removed with a release note |

## Deprecation policy

A DSH version leaves the compatibility matrix only via a release that:

1. states the removal and the replacement path in its notes, and
2. keeps at least one supported DSH version listed.

The plugin never silently widens or narrows its declared range; protocol
mismatches surface as `INCOMPATIBLE` in the tab with the exact versions.

## SBOM generation (from `0.1.0-beta.1`)

Every release ships a CycloneDX document `dsh-plugin-manager-<v>.cdx.json`:

- Generated by `scripts/generate-sbom.mjs` from `pnpm list --json` at
  release-build time (runtime + dev dependency closure, pinned versions,
  licenses from package manifests).
- Stored beside the tarball in the release assets; its SHA-256 is recorded
  in `SHA256SUMS.txt`.
- Verified by `scripts/verify-release-assets.mjs` (presence + digest) once
  the generator lands; until then the verifier reports "sbom pending".

## Release checklist (per release)

1. Version quadruple updated and `verify:docs` green.
2. Full gate set green on the release commit (typecheck, lint, tests,
   coverage, build, lib reproducibility, pack, assets, docs).
3. Assets assembled + verified; SBOM generated and hashed.
4. Annotated tag on a reviewed commit; immutable GitHub release; artifact
   attestation attached (CI).
5. A clean-environment smoke install from the published assets
   (`test:install` both modes) recorded in the release notes.
